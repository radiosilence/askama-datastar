# askama_datastar

The glue between Askama, Datastar and axum, published to crates.io as `askama_datastar`:
rendered markup (`Html`) that pages embed and patches send, SSE answers and streams,
Datastar's request header and signals, and Datastar's script, vendored. Datastar's own SDK
(`datastar`) writes the events; this crate builds on it. radiosilence's servers with a web
UI depend on it (koan, slsk-mcp, tubele-rs, mariastew, mcp-gateway, dither), and the kōan
standard (koan's `STANDARD.md`, §8) says what they use it for.

## Git

- Work in PRs; never push to main. PRs are squashed; merge main into a branch rather than rebasing.
- Never push tags or run `cargo publish`. CI tags and publishes when a release PR merges.
- Commits are signed.

## API

A library other projects depend on. A change to anything `pub` is a semver question:
breaking changes wait for a minor release while the version is 0.x, and the release PR's
`Semver` job fails a bump that does not allow for them. The SDK's types are part of the
API (`Html::patch` returns `PatchElements`), so a breaking SDK release is a breaking
release here.

Something goes in only when three of the servers need it; a piece one server needs stays
in that server. Each piece works alone, so a server can take one without the rest.

## Invariants

- **A fragment is written once.** The markup a page embeds and the markup a patch sends
  come from one template; nothing here renders a second version for updates.
- **No `\r` reaches an SSE line.** `Html::patch` normalises line breaks as an HTML parser
  does; tested in `tests/patches.rs`.
- **No cache keeps an event stream.** `events` and `stream` send `Cache-Control: no-store`.
- **The vendored script is upstream's.** `assets/datastar.js` is the release's
  `bundles/datastar.js`, byte for byte: a unit test checks its first line against
  `script::VERSION`, and CI's `Datastar script` job downloads the release and compares.

## Changelog

`CHANGELOG.md` is generated by `scripts/changelog.py` and never edited by hand. Every change adds one fragment under `changelog.d/unreleased/<section>/`, named `<pr>-<slug>.md` and holding one `- **Lead.** Detail.` entry; to correct a note, edit its fragment. `just changelog --stdout` previews the result. The format is in `changelog.d/README.md`. `scripts/changelog.py` and `scripts/test_changelog.py` are copied verbatim from koan.

## Releasing

`just release patch|minor|major` (or an exact `X.Y.Z`) branches from main, bumps `Cargo.toml`, `Cargo.lock` and the README's dependency line, turns the unreleased fragments into the version and opens the release PR; `gh workflow run release.yml` does the same from CI, with the `RELEASE_TOKEN` secret. Merging it is the release: CI publishes the crate with the `CARGO_REGISTRY_TOKEN` secret, then the GitHub release with the changelog section as notes. A push releases only when it changes the version; `gh workflow run ci-cd.yml` on main retries a release that failed part way. Main carries 0.0.0 until the first release, and 0.0.0 is never published.

A new Datastar release: `just datastar X.Y.Z` writes `assets/datastar.js` and `script::VERSION`; add a changelog fragment saying what the release changes for pages, then release.

## CI

`.github/workflows/ci-cd.yml` is one workflow: CI jobs gated on the domains a change touches (worked out by its `changes` job), the `Checks` job the ruleset requires, then the release jobs on main. A skipped job is a domain the change did not touch and passes `Checks`. A new directory of code, or a new job, needs adding to `changes` and to `Checks`'s `needs`. It also runs twice a week on main, to keep the caches and audit unchanged code; a scheduled run releases nothing.

## Check

```sh
just check   # fmt --check, clippy -D warnings, tests, docs, changelog, actionlint
just fast    # Cargo.lock and format, in seconds; the pre-push hook

```

## Where things live

| File | What |
|---|---|
| `src/html.rs` | `Html`: rendered markup, `HtmlSafe`, its patch and its response |
| `src/sse.rs` | `events` and `stream`: the SSE responses |
| `src/request.rs` | `is_datastar`, `require_datastar_on_post`, `Signals` |
| `src/script.rs` | The vendored script: `VERSION`, `SOURCE`, `url`, `serve` |
| `assets/datastar.js` | Datastar's `bundles/datastar.js` at `VERSION`; written by `scripts/datastar.sh` |
| `tests/` | The public API end to end: the wire format, responses, requests, the script, fragments |
